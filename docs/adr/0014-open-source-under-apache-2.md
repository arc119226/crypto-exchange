# ADR-0014:以 Apache-2.0 開源,貢獻走 DCO 而不是 CLA

- 狀態:已採納(Accepted)
- 日期:2026-09-12
- 相關:`LICENSE`、`NOTICE`、`AUTHORS`、`THIRD-PARTY-NOTICES.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`.github/`、`SECURITY.md`、`docs/limitations.md`;ADR-0000(需求訪談決策)、ADR-0008(工具鏈釘版)、ADR-0012(CI 跑在自建 runner)

## 背景

這個專案從第一天就被定位成商業原型。ADR-0000 第 25 行寫著商業形態是「白牌 / 交易引擎授權」,`docs/plan-v1.0.md` §2.1 寫得更明白:「一個**可授權給他人自架交易所的白牌交易引擎的商業化原型**」。

一年下來的實況是:258 個 commit、24 個 migration、527 個測試函式(其中 190 個要真的 Postgres)、一次零缺陷的發布路徑首跑,全部由一個人在業餘時間完成。而那條商業化路徑需要的東西——牌照、實繳資本、24/7 團隊、安全稽核、參考客戶——沒有一樣是再多寫幾行程式能換到的。

維護者的話是:「我一個人的時間有限,想公開,讓大家去玩。」

公開之前做過一次完整的開源就緒稽核(六個面向,每條發現由兩個對立視角查證)。結論是**工程完整、發布的配套一項都沒有**:沒有 LICENSE、沒有貢獻文件、沒有漏洞回報管道、沒有免責聲明,而 CI 會在 fork 的 PR 上執行維護者家裡那台機器。前兩項由這則 ADR 處理,第三項在上一個 PR 處理(`SECURITY.md`、`docs/limitations.md`),最後一項見下面決定 3。

## 決定 1:Apache-2.0

依賴圖不擋任何選擇,這點是逐項查過的:33 個直接依賴裡沒有 AGPL、SSPL、BUSL 或非商用條款;唯一的 copyleft 是 `pgregory.net/rapid`(MPL-2.0,檔案級,import 不觸發),以及 `tools/go.mod` 裡的 `golangci-lint`(GPL,但只在 build 時跑,不連進任何產物)。

**go-ethereum 比看起來輕。** 它把授權切成兩半:`cmd/` 底下是 GPL-3.0,函式庫是 LGPL-3.0。這個專案只 import `common`、`core/types`、`crypto`、`ethclient` 與根套件,全部在 `cmd/` 之外,所以受 LGPL 而不是 GPL 拘束,自有程式碼的授權不受限制。`cmd/exchangectl` 連 geth 都沒有 import。

選 Apache-2.0 而不是 MIT,理由有兩個而且都不是品味:

- **專利授權。** MIT 沒有明示的專利條款。對一套處理錢的軟體,§3 的明示授權與專利報復終止條款是有實質意義的東西,不是樣板。
- **§4 的 NOTICE 機制。** 它給了一個標準的位置去交代 LGPL 的 go-ethereum 與大約七十個 Apache/BSD/MIT 依賴的歸屬。MIT 沒有對應的東西,只能自己發明一套。

**沒有選 AGPL-3.0**,雖然它才是保住 §2.1 那個生意的選項——誰把這套當服務跑又改了程式就必須公開修改,而著作權人仍然能賣商業例外。代價是企業用戶會繞道,而且它必須搭 CLA 才成立(見決定 2)。目標是「讓大家去玩」,不是保住一條沒有人力去走的商業路線。

**沒有選 BUSL-1.1**,因為它不是開源:OSI 不認,發行版不打包,而且「讓大家去玩」會被它先打一次折。

## 決定 2:DCO,不要 CLA

貢獻者在 commit 訊息裡加一行 `Signed-off-by:`(`git commit -s`),聲明他有權以 Apache-2.0 貢獻這段程式。沒有要簽的文件,沒有簽署資料庫,沒有要裝的第三方服務。`.github/workflows/dco.yml` 是全部的執行機制,二十行,自己寫的——一個人的專案少一個會易主、會改權限要求的外部相依比較好。

**代價要寫明白,因為它同樣不可逆:貢獻者保留自己寫的那部分的著作權,所以這個專案從第一個外部 PR 合進來的那一刻起,再也不能改授權。** Apache-2.0 是永久的。雙授權那條路關了。

這正是選 AGPL 時必須配 CLA 的原因,而 CLA 的成本是真的:要架 CLA assistant、寫一份協議、每個新貢獻者第一次 PR 多一道手續。對一個時間有限的維護者,那道手續會直接換算成更少的貢獻者。

## 決定 3:公開的倉庫一律跑在托管 runner 上,而且寫在程式裡

`ci.yml` 用的是 `pull_request` 而非 `pull_request_target`,所以 GitHub 執行的是 PR head 自己那份 workflow 檔。公開之後任何人都能 fork、改寫 `runs-on`、刪光步驟、只留自己一行。詳見 ADR-0012 的修訂段。

`runs-on` 因此跟著 `github.event.repository.private` 走,而不是靠「記得把 `CI_RUNNER` 變數刪掉」。設定要人記得,程式不用;而且誰之後再把變數設回去,也重新打不開那扇門。

**這則決定當初只切 `pull_request`,後來收斂成整個倉庫。** 理由與代價記在 ADR-0012 的修訂段第四點——簡短版是:公開之後托管分鐘免費且不計量,所以那台機器只買到約 13 分鐘牆鐘,而把合併與 tag 留在上面會讓 `release` 那個「發布不該依賴一台家用機器」的釘死變成半套。

## 決定 4:合併到 main 跑完整的 pipeline

`checks` / `integration` / `e2e` / `helm` 原本在合併到 main 時整批跳過,前提是「一次只有一個 PR 在飛」——那讓 merge commit 的樹和 PR head 的樹一模一樣。Dependabot 先破了一次(#41),外部貢獻者會徹底終結它。而且原本的成本理由(私有倉庫每分鐘計費)在公開之後歸零。

兩個前提同時消失,那四行 `if` 就沒有任何留著的理由了。`v*` tag 從 main 切,所以這也保證了發布是從一棵真的被測過的樹切出來的。

## 後果

**送出去的:** ADR-0000 第 25 行與 plan §2.1 描述的那個資產。Apache-2.0 之下,任何人都可以拿走整套、閉源、掛自己的品牌賣,不必付一毛錢也不必回饋任何東西。那三處敘述已經改寫,留著會誤導讀者。**這是知情之後做的選擇,不是疏忽。**

**換到的:** 一份可被檢查的紀錄。這個專案真正稀有的不是撮合——撮合到處都是,而且單市場 266 orders/s 離自己定的 1,000 還差 3.8 倍——而是「錢對不對」被寫成了可執行的斷言:金額路徑禁浮點由 linter 擋,`api` 角色改不動提現由 Postgres GRANT 擋,事件與業務資料同生共死由 outbox 擋,引擎被 `kill -9` 之後訂單簿一字不差由每個 PR 的 `helm` job 擋。那種東西只有公開才有價值。

**沒解決、記在這裡的三件:**

1. **模組路徑是個人帳號。** `go.mod` 是 `github.com/arc119226/crypto-exchange`,320 個檔案、986 處。要搬去組織必須在第一個人 `go get` **之前**,之後就是一道單向門(Go 對搬家的模組路徑沒有轉址)。
2. **第三方通知靠 `make notices` 而不是 CI 守。** `THIRD-PARTY-NOTICES.md` 由 `scripts/gen-notices.sh` 從模組快取產生,但沒有對應的 `gen-check`,所以依賴換了而沒重跑的話它會安靜地過期。應該補一個檢查。
3. **LGPL §4 對靜態連結 Go 二進位的「可重新連結」要求是灰色地帶。** `NOTICE` 誠實交代了連結的是什麼、版本、以及上游原始碼在哪,這是這個專案實際交付得了的;它不等於逐條滿足 §4(d)(0)。
